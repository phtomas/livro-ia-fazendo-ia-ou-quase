Tool Calling: com ou sem LangGraph

Um modelo pode solicitar o uso de uma ferramenta, mas quem a executa é a aplicação ou o ambiente de execução. LangGraph é uma alternativa para coordenar esse ciclo — não um pré-requisito para conectar ferramentas ou definir skills.

Distinção essencial: skill descreve como trabalhar; tool realiza uma operação; tool calling permite ao modelo solicitar a operação; LangGraph organiza etapas e estado quando necessário. O resultado deve ser conferido antes de declarar sucesso.

Sem LangGraph

O código apresenta ferramentas ao modelo, recebe a solicitação, valida nome e argumentos, executa somente operações autorizadas e devolve o resultado como ToolMessage. Pode ser implementado por SDKs e outros runtimes.

Com LangGraph

bind_tools() disponibiliza o esquema ao modelo. tools_condition decide a rota e ToolNode executa a função. A resposta da ferramenta volta ao LLM para conclusão ou próxima etapa.

Ver exemplo Python

Como executar os exemplos

Os dois exemplos usam a mesma ferramenta de soma. É necessário Python 3.11+, um modelo com suporte a chamadas de ferramentas e credenciais configuradas no ambiente.

python -m pip install -U langchain-core langchain-openai langgraph python sem_langgraph.py python com_langgraph.py

Configure OPENAI_API_KEY e OPENAI_MODEL com um modelo compatível. As chamadas remotas podem ter custo. Nenhuma chave deve ser colocada no código.

Cuidados necessários

A escolha do modelo não garante que ele chamará a ferramenta. A execução exige verificação dos argumentos, limites de repetição e validação do resultado. Para operações que mudam arquivos, enviam dados ou realizam compras, exija autorização e confirme os efeitos observáveis.
