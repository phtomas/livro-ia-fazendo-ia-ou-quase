Como aprender RAG
na prática

Um ensaio com dados fictícios, busca local, critérios mensuráveis e geração opcional por modelo local. Não basta obter uma resposta bonita: precisamos demonstrar de onde ela veio.

Primeiro, o fluxo correto

RAG envolve duas etapas distintas: preparar o material consultável e depois recuperar informação para responder a uma pergunta. Neste laboratório a recuperação lexical funciona sem qualquer IA. A busca vetorial e a geração são extensões opcionais.

O que você vai aprender

Você criará um índice consultável, recuperará trechos de três arquivos de exemplo, testará a qualidade da recuperação e montará o contexto enviado ao modelo. Depois poderá experimentar geração e embeddings locais com Ollama.

O roteiro de execução

Baixe o projeto pelo botão Code → Download ZIP do GitHub e extraia-o. Abra o PowerShell na pasta laboratorio/rag-pratico. No Linux/macOS, use python3 no lugar de python. Nenhum Git instalado é necessário.

1
ETAPA 1

Verificar o ambiente

Execute os sete testes do núcleo sem usar modelos ou serviços externos.

Terminal / PowerShellCopie e execute na pasta do laboratório
python --version
python -m unittest discover -s testes -v

Critério de conferência: Esperado: Ran 7 tests — OK

2
ETAPA 2

Preparar e indexar o conhecimento

Carregue três documentos fictícios, divida o texto em trechos e monte um índice lexical no SQLite.

Terminal / PowerShellCopie e execute na pasta do laboratório
python rag_lab.py index --data dados

Critério de conferência: Esperado: 3 arquivos/páginas, 3 trechos.

3
ETAPA 3

Recuperar trechos relevantes

Pergunte ao índice BM25 sem chamar um modelo de linguagem.

Terminal / PowerShellCopie e execute na pasta do laboratório
python rag_lab.py search --question "Qual sensor precisa de substituição preventiva?"

Critério de conferência: Esperado: fonte 02-inventario.txt.

4
ETAPA 4

Medir antes de confiar

Compare as fontes recuperadas com três fontes de referência conhecidas.

Terminal / PowerShellCopie e execute na pasta do laboratório
python rag_lab.py eval --gold testes/perguntas.json --top-k 2

Critério de conferência: Esperado: hit_at_k = 1.0; 3/3 casos.

5
ETAPA 5

Conferir o contexto enviado ao LLM

Mostre instruções, texto recuperado e marcadores de fonte — sem chamar nenhum modelo.

Terminal / PowerShellCopie e execute na pasta do laboratório
python rag_lab.py answer --question "Qual sensor foi marcado para substituição preventiva?" --dry-run

Critério de conferência: Esperado: PREVIEW, [F1] e modelo_executado: false.

6
ETAPA 6

Gerar a resposta no Ollama (opcional)

Instale Ollama separadamente, baixe o modelo e experimente uma resposta fundamentada.

Terminal / PowerShellCopie e execute na pasta do laboratório
ollama pull llama3.2:3b
python rag_lab.py answer --question "Qual sensor foi marcado para substituição preventiva?"

Critério de conferência: Verificação humana: resultado aponta S2 e identifica o inventário.

7
ETAPA 7

Comparar busca vetorial (opcional)

Baixe o modelo de embeddings, indexe os mesmos trechos em vetores e consulte-os.

Terminal / PowerShellCopie e execute na pasta do laboratório
ollama pull nomic-embed-text
python rag_lab.py embed
python rag_lab.py search --mode vector --question "Qual sensor deve ser trocado?" --top-k 3

Critério de conferência: Verifique a fonte, a relevância e o tempo. Não suponha melhoria.

Como conferir os resultados

Os comandos mostram resultados esperados em cada etapa. O teste automatizado verifica as funções locais; a resposta de um LLM deve ser comparada manualmente com os documentos de origem.

Cuidados de uso

Atenção: o índice lexical pode recuperar um trecho que compartilhe palavras, mas não responda à pergunta. Citações não equivalem a verificação. Instruir o LLM a ignorar instruções nos documentos não impede todas as injeções de prompt. Use apenas documentos fictícios neste ensaio.
